# Regla de desarrollo

## Cambios acotados y verificables

Antes de cambiar código, identifica el componente responsable, lee su README y sigue los patrones existentes; no introduzcas tecnologías que el proyecto aún no haya decidido. Implementa el cambio mínimo que cumpla el requisito. Si cambia comportamiento, añade o actualiza una prueba enfocada y ejecuta la validación documentada para ese componente. Si no hay una prueba o comando aplicable, indícalo explícitamente en el resultado.
